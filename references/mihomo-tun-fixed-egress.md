# Mihomo TUN 与固定出口

## 推荐场景与取舍

TUN 是本 Skill 的首选架构。它在系统网络层接管整机流量，更容易覆盖 CLI、子进程、辅助程序和 CCBaga 浏览器；历史会话中实际采用和验证过的也是 TUN。

这项选择会影响整台 Mac 的日常联网：网站、应用、DNS、局域网访问、会议和远程开发都可能受到出口、延迟、规则和节点可用性的影响。固定、稳定、长期不移动的 Mac 最适合此模式。跨国家切换节点或频繁手动换节点会改变公网出口，可能影响服务身份、登录验证、连接和访问延迟。完成接入后尽量固定一个稳定节点；不要把手动频繁切换作为日常调优手段。移动设备需要随着网络位置频繁调整时，应先比较专用进程代理的试验成本。

## 出口与直连规则

要求用户提供订阅和可用节点范围。实际部署当天从当前 Mihomo 文档确认 TUN、DNS、路由、规则和配置字段，不沿用旧机器的端口、配置路径或过时字段。

目标规则应表达清楚：

- 仅用户确认的国内目标和明确列出的 IP 直连。
- 其他公网目标使用单一、固定的代理节点/策略组，禁止意外回退到 DIRECT。
- 保持用户确有需要的 LAN、SSH、Tailscale/tailcat、UU、Simulation 服务及远程维护路径可达。逐项确认这些目标按地址段、接口和使用场景走正确出口。
- 保持出口和规则选择可追溯，配置变更后重新核对规则命中和公开出口。
- 分别观察 Claude/浏览器连接到本机 Mihomo 的入口，以及 Mihomo 为各类目的地选中的远端出口。按域名或规则分流时，逐项记录出口；“客户端连接到 127.0.0.1”只能说明流量进入本地代理，不能说明最终经哪个节点出站。
- 对外代理监听使用一个统一端口，并让系统代理、CLI、浏览器相关入口和控制面读取同一设置。历史设备上用户明确偏好 7890；在迁移环境中先确认现存客户端如何监听和设置系统代理，再采用唯一端口，避免同时保留 7890/7891 一类入口造成流量分叉。
- Mihomo 控制面只绑定本机或受控管理网。控制接口的监听地址、认证 Secret 和访问边界按最新官方说明设置。Mihomo 文档提醒 Unix socket API 的 Secret 校验行为与常见控制器不同，不要自行假设其受认证保护。

DNS 解析策略要和出站规则匹配。分别检查浏览器 DNS、系统 resolver、IPv4/IPv6 以及应用内 DNS over HTTPS；网页工具只能观测它发出的查询。不要因网页显示一个代理出口就推断所有系统解析都使用同一出口。

## 建议的落地顺序

1. 保存现有网络状态和可回退配置，确认当前活动网络服务、默认路由、DNS 和远程维护方式。
   如果执行者是经这台 Mac 的代理联网的 Agent，先告诉用户：更改 TUN、系统代理、DNS 或路由可能立刻切断当前 Agent 的网络访问，本回合可能中断。提前准备原配置和手动恢复步骤，提醒用户断线时切回原代理/网络后重新连接 Agent。继续前还要确认用户能在本机操作恢复，或有一条不依赖待改链路的远程恢复入口。
2. 下载当前 Mihomo 稳定版并由用户安全地提供/导入订阅；不把订阅 URL 或完整配置回显到聊天。
3. 启用 TUN 和系统所需授权，建立直连白名单、固定代理出口、DNS、IPv4/IPv6与代理故障策略。
   核对订阅更新会否覆盖本地规则；若会，把固定节点选择和白名单放到客户端支持的持久覆写层，并在每次更新后重新核对规则与出口。
4. 先验证必要直连路径和远程维护仍通，再验证普通公网流量与 Claude/浏览器出口。
5. 按 [网络检查工具目录](network-check-tools.md) 交叉核对，并按 [登录与 CLI 验收](login-and-cli-acceptance.md) 确认进程树与正常工作。
6. 记录节点标识的脱敏值、规则选择、实际版本和恢复原网络的步骤。变更节点、规则或订阅后重新执行相关验收。

配置失联恢复时优先对同一固定节点执行已有客户端支持的重连/健康探测，并保持代理断开期间阻断未授权公网流量。不要因短时探测失败自动切到跨国节点或 DIRECT。若确需备用节点，提前由用户选定稳定候选和切换条件，并把切换作为会改变出口身份的显式操作记录；不新增常驻轮询任务来追踪节点。

是否需要自动健康探测、重试和断线重连，应在网络规划时明确。优先使用 Mihomo 客户端已有的节点健康与重连机制；每次恢复都保持固定出口策略和 fail-closed 行为。新增 launchd/后台常驻组件前，先说明它监控什么、失败时如何处理及是否需要管理员权限。

## 节点选择

节点推荐依据真实、可重复的观测：稳定性、丢包、延迟、出口 IP 和 ASN/网络类型、服务区域可达性、DNS 一致性，以及供应商使用条款。不要仅凭节点名称或某个 IP 信誉网站的分数判断。固定节点应是用户订阅中可长期使用、出口较稳定且满足其合法使用区域的节点。

## 已验证边界

过往过程只对 TUN 架构有实际验证记录。历史结果仅适用于当时的 Mac、Mihomo 配置、订阅和网络；不能据此保证不同供应商、节点或系统版本均无泄露。当前部署仍须按进程、正常工作与故障状态重新验收。
