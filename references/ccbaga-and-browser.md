# CCBaga 与浏览器

## 组件定位

CCBaga 是必选组件；它本身提供独立指纹浏览器，并兼有多账号身份切换能力。流程中不再把“CCBaga”和另一款指纹浏览器描述成两个必装组件。用户日常浏览器继续承担日常用途，Claude 工作身份在 CCBaga 管理的独立浏览器环境中使用。

## 安装前检查

从 [CCBaga 官方仓库](https://github.com/liseami/CCBaga) 检查最新发行版、macOS 支持、签名/更新方式、安装要求和当前功能说明。版本在执行时选择最新稳定版，不写死版本号。理解应用会保存哪些账户、浏览器 profile 与本机状态，配置路径和导出/备份能力以当时官方说明为准。

若 CCBaga 在部署日不支持目标 macOS、无法提供预期的独立浏览器或来源无法确认，暂停安装并报告具体差异；不得静默换成另一款产品并仍宣称完成。

## 建立干净身份

- 先备份用户希望保留的既有 Claude 配置，再通过 CCBaga 建立干净工作身份。
- 让用户明确选择新身份的名称和用途。新身份使用独立的 CCBaga profile 与站点数据，不继承日常浏览器 Cookie、缓存或个人登录状态。
- CCBaga 的多账号切换是可用能力；本地单身份接入仍按一个新工作身份验收。并行运行、多账号数据隔离属于可选扩展。
- 语言、时区、地区显示与定位权限按用户实际工作地区设置，并与固定出口所在地区保持一致。先使用 CCBaga profile 级设置；需要改 macOS 全局语言、时区或定位权限时，按 [系统语言、时区与地区](macos-timezone-and-locale.md) 记录原值、设置、验证并保留回退。
- Claude 界面显示的时间与整机系统时区是两处设置，分别核对：应用内有显示时区设置时先改应用内，需要整机一致时再改 macOS，并向用户说明影响范围。
- 登录、验证码、支付、授权和钥匙串提示由用户在本机可信界面亲自完成。代理订阅、密码、令牌和验证码不进入对话、脚本参数或日志。

## 浏览器网络与证据

CCBaga 浏览器及其辅助进程必须受网络出口策略约束。对浏览器做的公共 IP、DNS、WebRTC 检查只能说明测试页面观测到的浏览器请求结果，不能证明 Claude Code 子进程或系统其他网络路径已受控。反过来，Mihomo 控制面显示节点已连接也不证明浏览器侧的 DNS 或 WebRTC 行为正确。

CCBaga 项目中的环境检查可以作为一种观测来源。会话研究发现，项目对部分网络泄露检查的独立性有说明限制；部署时重新看当前实现和页面含义，并用独立第三方页面交叉检查。具体工具入口见 [网络检查工具目录](network-check-tools.md)。
