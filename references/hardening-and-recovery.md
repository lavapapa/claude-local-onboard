# 加固与恢复

## 最小必要加固

- 将代理订阅、节点凭据、控制接口 Secret 和认证材料保存在受保护的本机配置或系统凭据存储中；工具输出需脱敏。
- Mihomo 管理接口限制在本机/受控管理路径，并设置当前版本支持的认证。检查控制接口不可被 Claude 读取或无意修改的边界；同时保证配置文件权限与更新方式仍便于用户自己维护。
- 修改 Mihomo 管理接口的认证、监听地址或配置权限前，先盘点调用该接口的健康检查、启动器和监控任务，确认它们兼容改动并说明是否需要重启。评估重启对当前出口和远程维护的影响，再按用户授权安排变更。
- 出站控制覆盖 Claude Code 全进程树和 CCBaga 浏览器，并验证直接启动入口仍受网络策略约束。
- 默认不安装新的 launchd 定时任务、常驻轮询或看门狗。若用户明确需要持久自动恢复，再解释启动、权限和失效行为后设计。
- 保持系统改动可逆，记录原网络服务、DNS、代理状态和恢复步骤。

## 失效与恢复说明

整理一份用户可直接照做的恢复卡片：如何关闭 Mihomo TUN/网络扩展；如何恢复原 DNS/路由；如何确认默认网络恢复；如何重新开启固定节点；如何定位配置与安全备份。命令和 UI 操作以部署当时的 macOS 与 Mihomo 版本核实，避免复制旧会话中的机器专属路径、端口和节点。

若发现出口变化或直接连接：

1. 先暂停 Claude Code 和浏览器中的敏感操作。
2. 核对节点、规则命中、DNS 与当前出口，保留脱敏诊断信息。
3. 恢复到最后一个已知正常网络配置；若 TUN 变更影响正常网络，按恢复卡片回退。
4. 修复后从网络检查工具、CLI 和浏览器重新确认相关路径，再恢复使用。

不要为减少告警而扩大直连范围，也不要把失败的检测结果隐藏或写成通过。

## 最终交付摘要

提供一份短的本机交付记录，含：

- macOS 与当前安装软件版本、官方来源和日期；
- Claude Code 的统一安装/启动入口，CCBaga 工作身份说明；
- Mihomo 运行方式、脱敏后的固定节点标识、白名单规则位置；
- 旧 Claude 数据备份位置，以及原目录已清理的范围；
- 第三方工具与本机路径的验收结果、未覆盖项及证据时间；
- TUN 影响日常网络的说明、节点切换建议与完整恢复步骤；
- 用户尚需亲自完成的账号、支付、系统授权或确认。

远程接入、多账号并行和额度调度只在用户提出后形成扩展交付，不把它们混入本地核心验收。
