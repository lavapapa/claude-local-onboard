# 网络预验收、登录与 CLI 验收

先在未登录状态验证网络和启动路径，再让用户登录。这样可以在账号操作前发现出口、DNS 或旁路问题；登录后再用实际服务请求确认 CLI 身份与出口。

## 登录前环境验收

使用 CCBaga 的空白工作 profile 和未登录的 Claude Code，检查：

1. **固定出口**：浏览器与 CLI 的公网出口符合选定节点；使用多个 IP 观测端点交叉核对。IP 信誉结果仅作参考。
2. **DNS 与地址族**：检查 DNS、IPv4、IPv6 是否符合预期，确认无意外直连。
3. **浏览器网络**：在 CCBaga profile 检查 WebRTC/STUN 与 UDP；记录测试端点和实际覆盖范围。
4. **进程覆盖**：识别 Claude Code 主进程、子进程、辅助进程，以及 CCBaga 浏览器的网络进程，确认均受选定网络策略约束。
5. **入口与旁路**：从日常终端及计划使用的 IDE、SSH 等入口启动；直接调用 Claude Code 二进制时也应继续受系统级网络策略约束。环境变量或 alias 本身不能证明旁路已受控。
6. **故障行为**：在可恢复且用户知情的条件下，确认代理停止、断网或 DNS 故障时相关流量按预期阻断，不静默直连。可能导致整机断网的故障注入须先说明影响并取得用户同意。
7. **日常兼容与恢复**：检查用户指定的国内网站、局域网、SSH、Tailscale/tailcat、UU、远程开发等工作流；确认用户能按恢复卡片回退网络配置。

网络检查工具的候选与适用范围见[网络检查工具目录](network-check-tools.md)。有必需项不通过时，回到对应配置阶段修复；关键覆盖项未验证时，先记录未完成，不进入账号登录。

## 登录准备

预验收通过后，指导用户在 CCBaga 的独立指纹浏览器中完成 Claude 登录、订阅付费、验证码及系统授权。由用户本人处理账号凭据、支付、钥匙串请求和验证码。确认 Anthropic 当前认证方式与账号权益说明后再操作。不要把认证 URL、Cookie、授权码或 token 复制到聊天、脚本参数或日志。

## 登录后 CLI 验收

1. 确认浏览器显示目标身份，Claude Code 登录状态与用户预期一致。
2. 从约定入口启动 CLI，确认实际调用的是已盘点的安装路径和配置来源；核对日常终端及计划使用的 IDE/SSH 入口。
3. 发起实际 Claude Code 请求，确认认证可用，并确认浏览器与 CLI 的请求仍使用选定固定出口。
4. 更新或重装后，重新核对入口一致性、直接二进制调用的网络约束和故障阻断行为。

逐项记录“预期、观察、证据、结果、日期/版本、未覆盖点”，不记录秘密值。结果使用以下状态：

- **已配置**：配置文件或系统选项已设置，但没有独立行为证据。
- **已观测**：测试路径在指定时刻给出预期结果。
- **故障时已验证**：受控故障下观察到预期阻断或恢复。
- **未覆盖**：未测试、工具无法覆盖或结果含糊。
- **不通过**：发现未授权直连、IP/DNS/WebRTC 泄漏或普通工作流被破坏。

不以单站点结果、绿色图标或一次 CLI 请求代表完整验收。任何必需项“不通过”时，回到对应阶段修复；完整进程覆盖、阻止旁路或故障时阻断尚未验证时，交付状态标记为未完成。
