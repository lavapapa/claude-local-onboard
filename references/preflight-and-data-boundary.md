# 目标盘点与数据边界

## 目标

把“能用 Claude”拆成几项可观察结果：用户能从指定入口使用 Claude Code；浏览器与 CLI 使用目标身份；Claude 相关网络请求经过指定固定出口；普通开发与日常网络仍可使用；旧身份与会话数据保持在隔离备份中或按用户要求彻底清除。

## 先确认的事实

记录 macOS 大版本和芯片架构、当前 Claude Code 安装方式与路径、Claude 配置目录、CCBaga 安装状态、Mihomo 状态、网络接口和常用远程工作方式。查明设备是否经常移动、哪些网络目的地必须直连、用户希望固定的国家/地区出口，以及代理订阅是否允许固定节点使用。

同时确认用户希望使用的系统/浏览器语言、时区、地区显示与定位权限，以及期望的出口地区。记录当前设置和目标值，再决定哪些由 CCBaga profile 控制、哪些需要调整 macOS 全局设置；时区、语言与出口地区保持一致，原值一并写入恢复材料。设置方法见 [系统语言、时区与地区](macos-timezone-and-locale.md)。

逐项问清旧 Claude 数据如何处理：

- 哪些配置、会话、项目状态、凭据记录需要留档。
- 用户是否需要可恢复备份；默认建议完整备份。
- 是否同意新环境不导入旧会话。旧会话迁移不推荐，备份可以按需查阅。
- 计划采用何种第三方清理项目，是否需要用户亲自确认清理范围。

重置或切换身份前还要检查正在运行的 Claude Code/Desktop 进程和未完成任务。区分三类数据：活动配置、用户希望恢复的身份/浏览器归档、构建产物与临时缓存。CCBaga 可能在身份切换时关闭其识别到的 Claude 进程；说明影响并和用户约定切换时机，已有账号归档与浏览器 profile 按用户的保留决定处理。

不要根据目录名推测 Claude 安装或凭据位置。先依据当时 Anthropic 官方说明、当前版本实际读写位置和第三方工具源码确认。特别留意用户级配置、项目级配置、会话历史、插件/Hook、自定义命令、MCP 配置、shell 启动文件、钥匙串条目和浏览器站点数据。

## 备份和清理顺序

1. 生成只读清单，记录目录、用途、体积和是否包含凭据；输出时遮蔽令牌、邮箱、完整 IP、订阅地址及个人路径中不必要的部分。
2. 选择可信且访问受限的备份位置，保留目录结构与文件权限。备份不得进入新 Claude 配置目录，也不得与 CCBaga 新身份共用浏览器数据。
3. 核对备份包含预期数据且可读取。若备份工具有“仅列出/预览”模式，先审阅清单再执行。
4. 使用经审阅的第三方清理项目或其可理解的原生流程处理旧 Claude 数据。先备份并确认备份可读取，再按工具设计执行；了解哪些资料会清理、哪些会保留。保留会话历史等内容可以是工具的正常行为，按用户的保留意愿处理。
5. 用户选择不保留某类数据时，先列出对应路径与含义，得到用户确认后再从原位置清理。不要只删除当前 CLI 二进制，也要核对用户级目录、shell 启动配置和相关浏览器 profile。
6. 建立全新配置后验证其目录与浏览器 profile 独立。只从备份恢复用户明确需要的非会话设置；逐项审阅后再做，避免把旧认证状态、Hook、MCP 和旧会话带入新身份。

## 第三方清理项目评估

会话中发现过 [claude-env-cleanup](https://github.com/pnedfff/claude-env-cleanup)，但历史过程未证明该项目曾在机器上实际执行。它可作为候选，不作为既定或官方工具。部署时先检查维护状态、源码、目标路径、是否默认只读、备份能力、删除规则、秘密信息输出及对 Claude 当前版本的覆盖情况。其仓库中的账号规避、账号养号或无法核实的封禁判断，不纳入本 Skill 流程。

执行清理前至少能回答：它会读取和修改哪些目录；删除是否可恢复；备份存到哪里；日志是否暴露秘密；当前版本会否遗漏新增目录。若工具不能明确回答这些问题，改用可审阅的原生流程，并把目录清单作为本次部署材料。

本机现有的 `maintenance/claude-cleanup` 会保护 `~/.claude/projects`、`sessions`、`history.jsonl` 等会话资料。使用前先做额外备份并确认备份可读，再依照用户意愿与工具的设计清理；若工具保留了这些资料，在交付记录中说明保留范围和位置。
