# 接入后的长期维护

首次接入验收通过后，本机环境仍会因 Claude Code 升级、代理订阅刷新、切换网络、安装插件或引入外部工具而发生漂移。本文档提供日常巡检、变更与故障恢复规范。

本维护指南仅覆盖**本机环境防泄漏与配置一致性**；账号注册、订阅购买、KYC/身份验证、Claude Desktop、平台风控或申诉不在覆盖范围内。

## 1. 修改设置前先确认哪份配置在生效

Claude Code 默认读取 `~/.claude/settings.json`，但环境变量 `CLAUDE_CONFIG_DIR`（由终端脚本或多账号路由工具注入）会把生效目录指向别处。

- 改权限、Hooks、环境变量或模型前，先确认当前会话实际的 `CLAUDE_CONFIG_DIR`；
- 多套配置并存时，明确本次是改单套还是同步修改全部；
- 大多数设置与沙盒策略不会对已打开的进程热生效，修改后须退出并重开 Claude Code 会话。

## 2. 升级后核实启动链与残留旧进程

按 [受控启动链](seatbelt-and-launcher.md) 部署的环境，调用链路为：
`~/.local/bin/claude` → `claude-network-run` → `sandbox-exec -f outbound.sb` → `~/.local/share/claude/versions/<版本>`。

- **常规自动更新**：新版本二进制落盘到 `versions/` 后会被包装器自动选中，但仍需确认 `~/.local/bin/claude` 未被重装操作覆盖回裸符号链接（`head -n 1 ~/.local/bin/claude` 应仍为包装脚本）。
- **清理版本漂移**：长周期运行后 `versions/` 下可能积压多个旧版本，且旧终端窗口里的 Claude 进程仍跑在旧版本或旧策略上。升级重要策略后，用 `ps aux | grep "claude/versions"` 盘点并按需重启旧会话。

## 3. 持续区分“代理路由层”与“进程沙盒层”

排查问题时不要混为一谈：

- **代理客户端 / TUN 层**：决定流量走哪个出口节点、DNS 在哪里解析、哪些日常应用走直连；
- **`sandbox-exec` 进程沙盒层**：决定 Claude 进程树能否绕过本地回环直连公网，以及能否触碰代理管理端口（如 `9090`）与订阅配置文件。

整机开启 TUN 时，沙盒内外的 `curl` 可能看到同一个代理出口 IP——**“出口 IP 正确”本身不能证明进程沙盒仍在生效**；只有沙盒内直连公网返回 `EPERM` 且真实 Claude PID 的 `sandbox_check` 为 `True`，才证明双层防护都在工作。

## 4. 固定出口的可观测基线

避免靠记忆判断“出口变没变”：

- 本地留存预期出口的国家/城市与 ASN 类型记录（若自建了本地健康检查，额外关注状态文件的新鲜度与近期断连次数）；
- 订阅更新后立即复查持久覆写规则（`FIXED-EXIT` 与兜底规则）是否仍生效，确认订阅刷新未把策略重置为自动测速切换或 `DIRECT`；
- 一旦发现出口漂移，先暂停 Claude Code 与独立指纹浏览器中的操作，查明节点与规则命中后再恢复。

## 5. 直连白名单必须显式可查

局域网、内网域名、SSH、Tailscale/ZeroTier 等 Mesh VPN、UU 远程/RustDesk 等远程桌面因延迟与打洞需求通常配置为 `DIRECT`：

- 所有 `DIRECT` 规则集中写在持久覆写配置中并注明用途，不在排查问题时随手加未记录的临时直连；
- 直连应用与远端通信时暴露本机真实公网 IP 属于正常设计，不会污染受 `sandbox-exec` 隔离的 Claude 进程；但应留意这类软件是否在公网 IPv6 或局域网端口上暴露了不必要的入站监听。

## 6. Agent 拥有 Shell 时的本地标识暴露面

`sandbox-exec` 拦截的是**网络出站**，不会隐藏本机文件、网卡信息或环境变量。只要 Claude Code 允许执行 Bash 命令，以下命令一旦运行并把结果打进对话，就会作为文本随 API 请求发送给模型：

- `ifconfig` / `ipconfig getifaddr` / `netstat -rn`（可能包含内网地址或校园网/运营商分配的公网 IPv6）；
- `env` / `printenv`（可能包含 `SSH_CONNECTION` 等会话来源）；
- `hostname` / `scutil` / `system_profiler`（主机名与硬件型号）。

治理优先级：
1. **分清威胁边界**：内网 RFC1918 地址（如 `192.168.x` / `172.16-31.x`）、Tailscale `100.64.0.0/10` 地址和普通本地主机名不含物理地理位置，无需过度敏感；真正带位置属性的是**公网 IPv4、公网 IPv6（如运营商/教育网原生 v6）及地区/ASN 文本**。
2. **窄范围命令拦截（补充手段）**：可在生效 `settings.json` 的 `permissions.deny` 中加入 `Bash(ifconfig:*)`、`Bash(/sbin/ifconfig:*)`、`Bash(ipconfig getifaddr:*)` 防止无意调用，但不要试图拉长黑名单封禁 `env`、`python` 等日常开发命令——黑名单挡不住脚本或管道变体。

## 7. 工具输出脱敏钩子（可选进阶缓解层）

如果用户通过 Claude Code 的 `PostToolUse` Hook 部署了本地文本替换过滤服务（将工具输出中的本机真实公网 IPv4、地区/ASN 字样替换为代理出口或占位符）：

- **保持协议语义自洽**：本机公网 IPv6 命中时应替换为 `[redacted-ipv6]` 等明确占位符，不要替换成 IPv4 地址制造 `inet6 <ipv4>` 的假事实；
- **认清缓解边界**：事后字符串替换挡不住 Base64 编码、字符拆段、写文件分段读取，也不覆盖名单外的新地址；若 Hook 服务故障通常为 fail-open。它能有效降低日常误打印公网地址的概率，但不能当作硬安全边界；同时若使用了不经过 Claude Hook 的外部子 Agent，需注意覆盖盲区。

## 8. 技能、插件与 MCP 的出网及同步边界

- 核查配置中是否开启了从云端账号自动同步技能或插件的实验开关，按需固定本地可控版本；
- 新增第三方 MCP Server 或 Hook 脚本前，确认它是在 `claude` 子进程树内运行（自动继承 `sandbox-exec` 出站限制），还是作为独立后台服务运行在沙盒外；独立服务若会发起公网请求，必须同样显式配置本地代理；
- 移除不用插件或软链技能时同步清理残留配置与失效软链。

## 9. 外部账号与会话路由工具（Orca、Paseo、CCBaga 等）

引入外部编排器或身份切换器前，先核清它实际改写的是哪一层：

- 是通过环境变量切换 `CLAUDE_CONFIG_DIR`，还是直接覆盖 `~/.claude` 与 `~/.claude.json`；
- 切换身份时是否会强制杀掉正在运行的全部 Claude 进程；
- 钥匙串凭据是按账号独立命名还是共用同一服务名；
- 调用 CLI 时走的是 `~/.local/bin/claude` 受保护入口，还是直接指向了 `versions/` 下的裸二进制（后者会绕过启动器，必须修正回统一入口）。

## 10. 多账号隔离原则（按需扩展）

仅当用户存在多账号使用需求时适用：

- 每套账号使用独立的 `CLAUDE_CONFIG_DIR` 与独立钥匙串凭据、独立浏览器 Profile；
- 明确区分可共享的只读资产（通用指令、技能、插件）与严禁混用的状态（`projects/`、`sessions/`、`history.jsonl`、OAuth 凭据）；
- 同一工作目录的同一会话文件不要用两个账号交替续写。

## 11. 变更账本、局部回滚与定期自检

- **变更留痕**：每次修改 `outbound.sb`、启动器、`settings.json` 或代理覆写规则前先留带时间戳的备份（如 `outbound.sb.bak-YYYYMMDD`），记录改动原因、验证命令输出与回滚路径。
- **局部回滚**：出现问题时只回滚对应文件，绝不把旧备份整目录覆盖回活动配置目录；共享后台服务优先使用“热重载配置”，避免粗暴重启打断其他正在运行的会话。
- **定期复跑巡检**：换网络、更新客户端或续订节点后，复跑 [验收文档](acceptance-and-delivery.md) 中的**探针 A** 与出口/DNS/WebRTC/时区核对，及早发现环境漂移。
